# Correction complète des flux produits Google Merchant Center + Meta Catalog

Le projet Homestorys génère actuellement des flux produits destinés à :

* Google Merchant Center
* Google Shopping / Performance Max
* Meta Commerce Manager / Meta Catalog

Le domaine public utilisé est :

`https://homestorys-flux.eteamsys.be`

Exemple d'endpoint actuellement concerné :

`https://homestorys-flux.eteamsys.be/api/feeds/meta/fr.csv`

Certains endpoints retournent actuellement des erreurs HTTP, notamment 500/505, ce qui empêche Google Merchant Center et Meta Catalog de récupérer les flux.

Ta mission est de **diagnostiquer, corriger et fiabiliser l'ensemble des endpoints de flux Google et Meta**.

Ne corrige pas uniquement l'URL d'exemple.

Audite et corrige TOUS les endpoints concernés.

---

# 1. OBJECTIF FINAL

Tous les flux doivent être accessibles publiquement via une requête HTTP GET standard depuis un service tiers externe.

Ils doivent fonctionner :

* depuis un navigateur privé ;
* via curl ;
* via Google Merchant Center ;
* via Meta Commerce Manager ;
* sans session Replit ;
* sans authentification ;
* sans cookie ;
* sans token dans l'URL ;
* sans URL de preview ou workspace.

Les URLs doivent être stables après redeployment.

---

# 2. ENDPOINTS À AUDITER

Identifier automatiquement tous les endpoints existants correspondant notamment à :

```text
/api/feeds/meta/*
/api/feeds/google/*
```

Exemples possibles :

```text
/api/feeds/meta/fr.csv
/api/feeds/meta/de.csv

/api/feeds/google/en.xml
/api/feeds/google/it.xml
```

ou leurs variantes CSV / TSV / XML actuellement utilisées.

Ne pas supposer les noms exacts : inspecter le code.

---

# 3. DIAGNOSTIC OBLIGATOIRE

Pour chaque endpoint :

1. effectuer une requête GET externe ;
2. relever le status HTTP ;
3. relever le Content-Type ;
4. vérifier les éventuelles redirections ;
5. vérifier le temps de réponse ;
6. vérifier si la réponse contient réellement le flux ;
7. vérifier si une authentification/session est requise ;
8. vérifier si le comportement diffère entre environnement dev et production.

Identifier précisément toute cause pouvant produire :

```text
HTTP 500
HTTP 502
HTTP 503
HTTP 504
HTTP 505
HTTP 401
HTTP 403
HTTP 404
```

Analyser notamment :

* erreurs serveur non catchées ;
* chemins fichiers invalides ;
* fichiers présents en développement mais absents en production ;
* variables d'environnement manquantes ;
* appels Shopify qui échouent ;
* timeout pendant la génération ;
* problème de streaming ;
* problème de headers HTTP ;
* problème proxy / custom domain ;
* middleware d'authentification ;
* route protégée ;
* dépendance à une session Replit ;
* redirect ;
* dépendance à localhost ;
* génération de feed trop lourde pendant la requête ;
* erreur CSV/XML ;
* caractères spéciaux mal encodés.

# 5. ARCHITECTURE À PRIVILÉGIER

Éviter si possible cette architecture :

```text
Meta/Google appelle l'URL
↓
requête Shopify complète
↓
transformation de tout le catalogue
↓
génération du CSV/XML
↓
réponse HTTP
```

Cette architecture peut provoquer timeout et erreurs serveur.

Privilégier :

```text
Shopify
↓
job de génération périodique
↓
feed généré et validé
↓
fichier stocké
↓
endpoint public
↓
lecture/stream du fichier déjà prêt
↓
Google / Meta
```

Le endpoint public doit être extrêmement simple et robuste.

```text

↓

```

---

# 8. META — FORMAT HTTP

Pour les feeds CSV Meta :

```http
HTTP/1.1 200 OK
Content-Type: text/csv; charset=utf-8
Cache-Control: public, max-age=300
```

Pour TSV :

```http
Content-Type: text/tab-separated-values; charset=utf-8
```

Pour XML :

```http
Content-Type: application/xml; charset=utf-8
```

Content-Disposition peut être :

```http
Content-Disposition: inline; filename="meta-fr.csv"
```

Ne pas forcer un téléchargement incompatible.

---

# 9. GOOGLE — FORMAT HTTP

Pour les flux Google XML :

```http
Content-Type: application/xml; charset=utf-8
```

Pour TSV :

```http
Content-Type: text/tab-separated-values; charset=utf-8
```

Pour CSV :

```http
Content-Type: text/csv; charset=utf-8
```

Ajouter :

```http
Cache-Control: public, max-age=300
```
