# Budget Pro AI — Style Reference
> A clinical blueprint for media budgets — near-black ink on paper-white cards, one hairline gray, and functional color reserved strictly for risk signals.

**Theme:** light

Budget Pro AI runs on a monochromatic "clinical blueprint" system: a soft gray canvas (#f5f5f5) holds pure-white paper cards (#ffffff), with near-black ink (#0a0a0a) carrying all primary text and the sidebar's active state. Inter is the only typeface — weights 400/500/600/700 across a tight 10–28px range, with no display face and no decorative type. The interface is intentionally achromatic everywhere except one place: risk and status signaling, where a disciplined five-color semantic palette (green/orange/red/black/grey) plus domain badges (blue for open, amber for partial, red for overdue) carry all meaning. Radii are large and soft (18–24px) on cards, pills, and nav items, giving a rounded, friendly "SaaS console" feel despite the strict grayscale base. Shadows are barely-there — a 1px hairline ring plus a soft ambient blur — so elevation reads as separation, not depth. The result is a dense, numbers-first admin console that stays legible and calm at scale: French financial ops staff scanning tables of clients, invoices, and sync alerts all day.

## Tokens — Typography

### Inter — The system's only typeface, used for every element from page titles to table cells to nav labels. Weight 600/700 for h1-level page titles (24–32px), 500 for card titles, section labels and active nav, 400 for body/table content. Sizes compress tightly at the low end (10–13px for eyebrows, badges, nav labels) reflecting a dense data-console density rather than a marketing site's generous scale. · `--font-sans`
- **Substitute:** system-ui, -apple-system, sans-serif
- **Weights:** 400, 500, 600, 700
- **Sizes:** 10px, 11px, 12px, 13px, 14px, 16px, 18px, 20px, 24px, 28px
- **Line height:** 1.0–1.5 (tight `leading-none` on KPI values and nav labels; relaxed on body copy)
- **Letter spacing:** wide/uppercase tracking (`tracking-widest`, `tracking-wider`) on 10–11px eyebrow labels and table headers; tight (`tracking-tight`) on page titles and KPI numbers
- **Role:** Universal — headings, body, nav, tables, badges, buttons, forms. No secondary or display face is ever introduced.

### JetBrains Mono — Reserved for the `--font-mono` token; not currently exercised in visible UI copy, held for technical/ID values (account IDs, tokens) if introduced. · `--font-mono`
- **Substitute:** ui-monospace, Menlo, Consolas, monospace
- **Weights:** 400
- **Role:** Technical identifiers only (account IDs, API keys) — never body or heading text.

### Layout

- **Page max-width:** 1280px (`max-w-7xl`), centered inside the content column
- **Sidebar width:** 224px (`md:w-56`), fixed, full-height
- **Header/topbar height:** 64px (`h-16`)
- **Page padding:** 16px mobile → 32px desktop (`p-4 md:p-8`)
- **Card padding:** 24px standard (`p-6`), 16–20px on dense KPI cards
- **Table row height:** 48px header (`h-12`), ~44px body rows (`py-3`)
- **Sticky elements:** page header sticks to the top of the scroll container (`sticky top-0 z-20 bg-background`); table column headers stick to the top of their own scroll box (`sticky top-0 z-10`) with an opaque background so scrolled rows never bleed through

## Components

### Sidebar Navigation Item
**Role:** Primary app navigation

Fixed 224px-wide sidebar (#fafafa) with a hairline right border. Items are 18px-radius pills, 13px medium-weight Inter, with a 16px lucide icon at 12.5% opacity gray (#737373) that darkens on hover. Active state fills solid ink (#0a0a0a) with white text/icon — the system's strongest visual statement. Items group under uppercase 10px tracking-widest gray eyebrows ("Operations", "Admin"). An unread-count pill (10px, bold, rounded-full) floats right-aligned inside active items.

### Filled Button (Primary)
**Role:** Primary action

Ink-soft (#171717) fill, white text, 18px radius, 1px border matching the fill color, Inter 14px/500. No hover animation (uses `hover-elevate`/`active-elevate-2` overlay utilities instead of color shifts). Used for 'Save', 'Add Client', form submissions.

### Outline Button (Secondary)
**Role:** Secondary action

Transparent/inherited background, 1px border at 8% black opacity, shadow-xs, inherits surrounding text color. Used for 'Cancel', 'Export', toolbar actions — pairs beside a filled button without competing.

### Ghost Button
**Role:** Tertiary / icon-only action

Transparent fill, transparent border until hover-elevate activates, no shadow. Used for icon-only actions in table rows (edit, delete, review) and the mobile menu trigger.

### KPI Widget Card
**Role:** Dashboard headline metric

White (or tinted danger/warning) card, 24px radius, 1px hairline border (or colored border for warning/danger states), card shadow (removed on warning/danger variants). Header row: 11px uppercase tracking-tight gray label + a 10px-radius icon plate (#f5f5f5 fill, ink icon). Value renders at 28px/600 tracking-tight; color shifts to amber (#d97706) for warning or red (#e7000b) for danger states, with a matching tinted background (#fff5f5 / amber-50).

### Data Table
**Role:** Primary content pattern across almost every page

White card (`rounded-md border`) containing a capped-height scroll box (`max-h-[500-600px] overflow-y-auto`). Column headers are 11–12px uppercase tracking-wider gray text on an opaque light-gray band (`#f5f5f5` or `bg-muted`), pinned via `sticky top-0` so they stay visible while body rows scroll beneath. Rows are 1px hairline-divided, hover-highlighted (`hover:bg-muted/50`), with right-aligned numeric/action columns.

### Risk Badge
**Role:** Client health indicator

Pill-shaped (4px radius) badge combining a 6px color dot with 12px medium-weight label text, at 10% background tint / 20% border tint of its semantic color: green (healthy), orange (invoice overdue), red (critical), black (exhausted/stopped), grey (awaiting launch). The dot-plus-tint pattern is reused for every domain status badge (invoice status, payment status, reminder level, alert severity) with slightly different palettes (blue=open, amber=partial, red=overdue).

### Sticky Page Header
**Role:** List-page and tab-header title block

`h1` (24-32px/700/tracking-tight, #0a0a0a) plus a muted description line, pinned to the top of the scrollable content area (`sticky top-0 z-20 bg-background` on list pages; `bg-card` with rounded top corners inside client-detail tab panels) so the title never scrolls out of view above a long table.

### Sidebar Logo Mark
**Role:** Brand identity

8x8 (32px) ink-black rounded-xl square containing a white lucide `TrendingUp` icon, paired with the wordmark "Budget Pro" (14px/600/tracking-tight) stacked above a 10px uppercase tracking-widest "AI" eyebrow.

### Language Toggle
**Role:** Locale switcher, pinned above the user chip

Inline "FR / EN" text toggle — active language gets the primary-fill pill treatment (ink background, white text), inactive language is plain muted-gray text. No flags or dropdown; deliberately minimal.

## Do's and Don'ts

### Do
- Reserve color exclusively for risk/status semantics (green/orange/red/black/grey badges, amber/red KPI states); everything else stays grayscale ink-on-paper.
- Use 18–24px radii consistently across buttons, cards, and nav pills — the rounded, soft-cornered language is the system's identity against its otherwise strict monochrome palette.
- Pin table column headers (`sticky top-0`) with an **opaque** background whenever a table scrolls; translucent header fills let scrolled rows bleed through and must never be used.
- Use the dot-plus-tint badge pattern (10% bg tint, 20% border tint, colored dot) for every status/severity indicator so risk badges, invoice status, and alert severity all read as one visual language.
- Keep the sidebar's active-item treatment (solid ink fill, white text/icon) as the single strongest visual statement on any screen — nothing else should compete with it in contrast.
- Use 11–13px uppercase tracking-wide/tracking-widest labels for table headers, KPI eyebrows, and sidebar section labels; this is the system's only typographic flourish.

### Don't
- Do not introduce a second accent color outside the five-value risk palette (green/orange/red/black/grey) — new statuses must map onto this existing scale, not invent new hues.
- Do not use heavy drop shadows or dark elevation; shadows stay at 1px hairline + soft ambient blur (`--shadow-card`) maximum.
- Do not apply sharp corners (<12px) to cards, buttons, or nav items — the rounded 18-24px language must stay consistent everywhere.
- Do not give a `<thead>` or sticky header a translucent (`/50`, `/30`, etc.) background — it breaks the pinned-header effect by letting scrolled content show through.
- Do not add a second typeface; Inter carries every weight and size in the system, including numeric/tabular data.
- Do not fill primary buttons with pure black (#000000) — always use the slightly softened ink (#171717) reserved for `--primary`, keeping #0a0a0a exclusive to text and the active nav pill.

## Elevation

- **Standard cards:** `0 0 0 1px rgba(23,23,23,0.05), 0 1px 3px rgba(0,0,0,0.10), 0 1px 2px -1px rgba(0,0,0,0.10)`
- **Inputs / small controls:** `0 1px 2px rgba(0,0,0,0.05)`
- **Warning/danger KPI cards:** no shadow — replaced by a colored border (`border-amber-200` / `border-[#fecaca]`) and tinted fill instead of elevation

## Imagery

There is no photography or illustration in this system — it is a pure data console. The only "imagery" is functional: Recharts bar/line charts using the chart-1 through chart-5 palette (blue, green, orange, purple, red) for cashflow and consumption visualizations, and lucide-react line icons (16-20px, 1.5-2px stroke) used consistently for nav items, KPI card icons, and inline row actions. Icons are always monochrome (ink or muted-gray), never colored, except when they inherit a KPI card's warning/danger tint.

## Layout

A fixed 224px sidebar (desktop) or collapsible sheet (mobile) sits left of a single scrolling main column capped at 1280px and centered with 16-32px outer padding. Every list page follows the same rhythm: a sticky title+description header, optional filter/search toolbar, then one dominant white card containing a capped-height, independently-scrolling data table. The client-detail page extends this into a tabbed sub-layout (Invoices/Payments/Consumption/Alerts/Reminders/Credits) where each tab repeats the same sticky-header-plus-scrolling-table pattern inside a shared card shell. The dashboard breaks the table-first pattern with a KPI grid (24px-radius cards) above chart panels and a "clients at risk" scrolling list — the only page allowed a denser, multi-panel grid layout.

## Agent Prompt Guide

**Quick Color Reference**
- text: #0a0a0a (primary), #737373 (muted/secondary)
- background: #f5f5f5 (canvas), #fafafa (sidebar), #ffffff (cards)
- border: #e5e5e5 (hairline)
- primary action: #171717 (filled button)
- danger: #e7000b (destructive, critical risk, overdue)
- warning: #d97706 / amber-50 bg
- success: risk-green `hsl(142 71% 45%)`

**3-5 Example Component Prompts**

1. Create a KPI card: white fill, 24px radius, hairline border, card shadow. Header row with an 11px uppercase gray label and a 10px-radius #f5f5f5 icon plate. Value at 28px/600 tracking-tight in #0a0a0a.

2. Create a primary button: 'Enregistrer' — 18px radius, #171717 fill, white text, Inter 14px/500, no hover color shift (elevate overlay only).

3. Create a risk badge: 4px radius pill, 6px colored dot + 12px medium label, background at 10% opacity of the semantic color, border at 20% opacity — e.g. green for 'Healthy', red for 'Critical'.

4. Create a data table: white card, capped `max-h-[500px]` scroll box, sticky `#f5f5f5` opaque header row with 11px uppercase tracking-wider gray labels, 1px hairline row dividers, hover state `bg-muted/50`.

5. Create a sidebar nav item: 18px-radius pill, 13px/500 Inter, 16px lucide icon at #737373. Active state: solid #0a0a0a fill, white text and icon.
